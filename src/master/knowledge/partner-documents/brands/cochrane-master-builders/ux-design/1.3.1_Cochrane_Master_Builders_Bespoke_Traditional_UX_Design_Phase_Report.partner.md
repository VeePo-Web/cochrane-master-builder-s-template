## 2. What this document is

The **UX design-phase contract** for CMB and its sister sites. It defines the bespoke / traditional / editorial register that every CMB-family site must hit: layout density, hierarchy choices, when to choose restraint over flash, mobile UX defaults, trust-signal placement, footer architecture, and the patterns that distinguish "bespoke craft" from "templated polish."

## 3. Decision triggers — when to consult this doc

- Layout and section density on any page (hero, services, areas, about, contact).
- Type scale, line-height, and rhythm decisions.
- Choosing between editorial restraint and animated flash.
- Mobile touch-target sizes, viewport breakpoint behavior, safe-area handling.
- Footer architecture and trust-signal placement.
- Form layout and step count.
- Trust signals on legal / warranty / license pages — where they sit and how they're framed.
- Reviews / testimonials placement and visual treatment.
- Hero image direction at the *composition* level (subject, framing, restraint).
- Any "is this layout bespoke or templated?" check.

## 4. Decision types this doc DOES NOT govern

- Brand voice / tagline / family-language → `brand-identity/1.2.x.partner.md`.
- Strategic positioning / what business CMB is in → `strategy/*.partner.md`.
- Persona empathy / objection handling → `personas-icp/1.4.x.partner.md`.
- SEO meta / keywords / Areas-We-Serve coverage list → `seo-research/1.1.partner.md`.
- Multi-trade backend taxonomy → `strategy/1.3.partner.md`.

## 5. How to read it

- Parse DOCX first via `document--parse_document`.
- Start with the layout / density section.
- For mobile decisions, jump to the responsive / mobile section.
- For footer or trust placement, find those specific subsections — they're the most actionable.
- For "is this bespoke?" sanity checks, look for the anti-pattern list.

## 6. Routing precedence

- **Wins** on layout, density, type scale, hierarchy, footer architecture, mobile UX defaults, form structure, and trust-signal placement.
- **Loses** to `brand-identity/1.2.x` on visual *register* (palette, type pair, tone of voice in UI copy).
- **Loses** to `strategy/1.3` on multi-trade structural questions that span sites.
- **Loses** to relevant `personas-icp/1.4.x` on copy register inside UI components (e.g. form labels for the subcontractor flow).
